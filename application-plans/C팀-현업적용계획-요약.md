## 1. 공통적으로 드러난 내용

### 1.1 교육 → 현업 이식의 공통 프레임

| 공통 주제 | 팀원들이 공유하는 방향 |
|-----------|------------------------|
| **단계적 도입** | 1차 시범(소규모·짧은 기간) → 2차 확대. 무리한 전사 도입 없음 |
| **Rules / 맥락** | Cursor Rules, `@` 문서·코드 첨부, 프롬프트에 **범위·금지 사항** 명시 |
| **검증은 사람+테스트** | AI 출력 후 **pytest·기존 테스트·리뷰** 필수. 민감 정보·의료·보안 영역은 **사람 최종 검수** |
| **문서·추적** | PRD·AC·작업 메모·Report — 「왜 했는지」를 남겨 이어하기 |
| **Magic Square 연계** | Dual-Track, ECB, Golden Master, RED→GREEN, Ask→Agent 등을 **그대로 또는 축소**해 언급 (이수진·이재호·윤지호가 가장 직접적) |

### 1.2 AI 활용 범위 (공통적으로 안전하다고 본 것)

- 문제 분석, 코드 초안, **국소** 리팩터, 리뷰 보조
- **하지 않기로 한 것**(여러 문서에 암시): 전체 앱/화면 일괄 생성, 테스트 삭제·약화, 민감 데이터 프롬프트 입력

### 1.3 리스크·전제 (거의 전원)

- 고객·환자·API Key·내부 URL 등 **프롬프트·첨부 금지**
- 사내 AI·네트워크·CI 정책 준수
- **아키텍처·DB·규제·실기기** 검증은 개발자/QA 책임

### 1.4 필요 지원 (반복)

- 팀 **공통 Rules·프롬프트 템플릿**
- **CI 테스트·커버리지** (가능한 범위)
- Tech Lead / QA / DevOps와 **Gate·GM·브랜치 규칙** 합의

## 2. 사람마다 다르게 강조한 내용

### 2.1 적용 깊이 스펙트럼

```text
[경량 운영]     이민준 · 이진범 · 이승환
      ↓
[환경 맞춤형]   윤지호 (TV/Tizen — UI는 수동, 로직만 테스트)
      ↓
[표준 TDD+팀]   이수진 (AC·GM·Phase 0 Gate·팀 역할 분담)
      ↓
[Legacy 대규모] 이재호 (10GB+ 의료 SW, Pilot·규제·다팀 SSOT)
```

### 2.2 개인별 차별 포인트

| 이름 | 다르게 쓴 핵심 | 대표 지표·도구 |
|------|----------------|----------------|
| **윤지호** | **Track A(UI/실기기) vs Track B(C# 로직)** 이원 검증. pytest 전체 목표 **안 함** | 수동 GM-TC-Home, worklog, 기기 검증 전 merge 0% |
| **이수진** | **팀 거버넌스** 표 — Tech Lead·DevOps·QA 역할·기한 | 1커밋=1 RED, Boundary 85% / Domain 95%, GM 0건 |
| **이재호** | **의료기기·Legacy** — Platform/Product, SaMD/QMS, 환자 데이터 금지 | dotnet test + coverlet, `docs/traceability/`, D+3~28 일정 |
| **이승환** | **Cline** 시범, 「규칙 없는 프로젝트」에 Rules 도입 | 2주 1건 완주, 프롬프트 양식 1종 |
| **이진범** | **Device Farm** — repo 단위 cov, **실기기**가 unit보다 중요 | pytest coverage, rule 파일 공유 |
| **이민준** | **PoC·내부 도구**, PRD→AI 초안, Discovery/Delivery 느낌 | 테스트 통과 여부, PRD 템플릿 요청 |
| **이영실** | — | (미작성) |

### 2.3 기간·단계 설계 차이

| 패턴 | 해당 멤버 | 1차 기간 |
|------|-----------|----------|
| **짧은 시범 (2주~1개월)** | 이승환, 이민준, 이진범 | 빠른 1건 완주 |
| **표준 시범 (4주)** | 이수진, 이재호 | 1 슬라이스 E2E |
| **유연 (2~4주)** | 윤지호 | 분석·리팩터 강화 먼저 |
| **장기 (3단계 12주~)** | 이재호만 3차「정착」명시 | 분기 단위 KPT |

### 2.4 AI 도구 선택

| 도구 | 누가 |
|------|------|
| **Cursor** (Rules, Ask/Agent) | 윤지호, 이수진, 이재호, 이민준, 이진범 |
| **Cline** | 이승환 (명시적 시범) |
| 미기재 | 이진범, 이민준 |

## 3. 현업 유형별 분석·요약

같은 「현업 적용 계획」이어도 **제품·스택·검증 환경**에 따라 전략이 갈립니다.

### 3.1 유형 A — **임베디드·TV UI** (윤지호)

| 항목 | 내용 |
|------|------|
| **환경** | C#, Tizen, VS, **빌드·UI 테스트 어려움** |
| **병목** | 실기기 배포, 리모컨·포커스·성능 |
| **전략** | 교육 패턴 **원칙만 차용**; AI는 분석·소규모·국소 리팩터 |
| **검증** | Track A = 수동 시나리오·스크린샷 / Track B = 단위·정적 (2차) |
| **팀 시사점** | **cov 숫자를 UI에 요구하지 말 것** — GM을 수동 체크리스트로 |

### 3.2 유형 B — **대형 Legacy·의료 SW** (이재호)

| 항목 | 내용 |
|------|------|
| **환경** | C# WPF .NET 4.8, Platform+Product, **10GB+** 빌드 |
| **병목** | 회귀·규제·Clinical·영상 Pipeline |
| **전략** | Magic Square를 **Pilot 1모듈**에 축소 이식 — Dual-Track, ECB, GM, Phase 0 Gate |
| **검증** | Entity cov ≥95%, Control/Boundary ≥85%, View = smoke+GM |
| **팀 시사점** | 이수진과 **거버넌스 언어 동일**(AC, GM, Gate) — **의료·다팀 SSOT**만 추가 레이어 |

### 3.3 유형 C — **인프라·Device Farm** (이진범)

| 항목 | 내용 |
|------|------|
| **환경** | 원격 Device Farm, **다수 repo**, legacy |
| **병목** | **실제 기기 동작** (unit만으로 부족) |
| **전략** | legacy 리팩터 + **pytest coverage** + rule 공유 |
| **검증** | cov 집계 + 기기 검증 (사람) |
| **팀 시사점** | 윤지호·이진범 공통 — **「Device/실기기는 사람」** |

### 3.4 유형 D — **규칙·프로세스 부재 프로젝트** (이승환)

| 항목 | 내용 |
|------|------|
| **환경** | AI 에이전트만 쓰고 **Rules 없음** |
| **병목** | 범위 이탈, 테스트 삭제, 맥락 유실 |
| **전략** | Rules + `@` + 단계 지시 + Ask→Agent + **pytest 필수** |
| **검증** | merge 전 테스트 통과, diff 크기·재질문 횟수 |
| **팀 시사점** | 회고 요약의 이승환 축과 일치 — **가장 범용·온보딩용** 템플릿 후보 |

### 3.5 유형 E — **TDD·협업 표준화** (이수진)

| 항목 | 내용 |
|------|------|
| **환경** | Boundary+Domain 분리 가능한 **기능 개발** |
| **병목** | RED/GREEN 혼용, AC·GM 불일치 |
| **전략** | 교육 커리큘럼 **가장 충실한 현업 이식** + 팀 역할·CI |
| **검증** | AC ID, GM approve, Phase 0 Gate, cov 85/95 |
| **팀 시사점** | **팀 공통 최소 규칙** 논의 시 baseline 문서로 적합 |

### 3.6 유형 F — **PoC·내부 도구** (이민준)

| 항목 | 내용 |
|------|------|
| **환경** | 소규모, 부담 적은 실험 장 |
| **전략** | PRD → AI 초안 → TDD 흐름 익히기 |
| **한계** | 상세 Gate·GM·ECB 없음 — **학습·습관 형성** 단계 |
| **팀 시사점** | 신규·주니어 **1차 목표**로 적합, 이수진/이재호 패턴은 2차 |

### 3.7 유형 G — **미정** (이영실)

## 5. 공통 vs 차이 — 한눈에

### 5.1 모두가 동의하는 「최소 공통분모」

1. **작게 시작** (1모듈·1repo·1기능)
2. **Rules + 맥락 첨부 + 범위 제한**
3. **테스트·리뷰로 AI 출력 검증**
4. **민감 정보 넣지 않기**

### 5.2 갈라지는 지점 (팀 규칙 논의 시)

| 질문 | 한쪽 | 다른 쪽 |
|------|------|---------|
| TDD·GM·Gate를 **필수**로 할까? | 이수진, 이재호 | 윤지호, 이진범, 이승환, 이민준 |
| **커버리지 숫자** 목표? | 85/95%, pytest cov | TV UI는 시나리오만; Device는 기기 우선 |
| **표준 도구** Cursor만? | 대부분 | 이승환은 Cline 시범 |
| **문서 깊이**? | traceability, gm_approval (이재호) | worklog·짧은 메모 (윤지호, 이승환) |

### 5.3 회고 요약과의 연결

| 회고 공통점 | plan에서의 현업 번역 |
|-------------|---------------------|
| TDD·단계 나누기 | Phase 0 Gate, 1커밋=1 RED, Ask→Agent |
| Rules·`@` | `.cursorrules`, Cline/Rules, Agent 4줄 헤더(이재호) |
| 리뷰 = 합의 | AC·GM·RED/GREEN in PR (이수진, 이재호) |
| Legacy·실기기 한계 | 윤지호 Track A, 이재호 Pilot, 이진범 Device |
