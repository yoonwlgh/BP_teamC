## 1. 대상 업무

- AI 에이전트를 통해 규칙 없이 운영 되는 프로젝트 
- 우선 **본인 담당 모듈 1~2개**부터 Cline 으로 시범 적용
- 교육에서 익힌 **TDD·문서 기반 프롬프팅**을 실제 업무에 옮기는 것이 목표

---

## 2. 적용 범위 (단계)

| 단계 | 기간(예상) | 범위 | 목표 |
|------|------------|------|------|
| **1차 (시범)** | 2주 | 본인 담당 기능 1건 (버그 수정 또는 소규모 개선) | Rules 설정, `@` 문서 첨부, pytest 확인까지 1회 완주 |
| **2차 (확대)** | 1~2개월 | 팀 내 유사 업무 2~3건, 코드 리뷰 시 AI 에이전트 활용 | 팀 공통 프롬프트 양식 1종 만들고, 리뷰·테스트 확인 루틴 정착 |

---

## 3. 구체적 활용 방안

- **Rules 파일**에 팀 코딩 규칙·금지 사항(예: `print` 금지, 테스트 약화 금지)을 적어 두고 매번 프롬프트에 반복하지 않기
- 작업 전 **`@README`, `@관련 문서`, `@수정 대상 파일`** 첨부해서 AI가 맥락을 먼저 이해하게 하기
- 프롬프트에 **"지금 하지 말 것"**(예: 다른 파일 수정 금지, 테스트 삭제 금지)을 명시하기
- **Ask mode**로 수정 방향·영향 범위를 먼저 확인하고, 괜찮으면 **Agent mode**로 구현하기
- AI가 수정한 코드는 **반드시 pytest(또는 기존 테스트) 실행** 후 커밋·PR 올리기
- 작업 끝나면 **짧은 메모(무엇을, 왜, 결과)** 를 남겨 다음에 이어서 작업할 수 있게 하기

## 4. 기대 효과·지표

| 항목 | 기대 효과 | 측정 방법(가능한 경우) |
|------|-----------|------------------------|
| **반복 설명 시간 감소** | `@` 첨부·Rules로 같은 설명을 줄임 | 작업 1건당 AI 재질문 횟수 (전/후 비교) |
| **수정 범위 축소** | 단계·파일 범위를 명시해 불필요한 변경 감소 | PR diff 파일 수·라인 수 |
| **품질 유지** | 테스트로 AI 코드 검증 | merge 전 테스트 통과율, 리뷰 지적 건수 |
| **이어하기 쉬움** | 작업 메모·Report 습관 | 중단 후 재개까지 걸리는 시간 |

## 5. 리스크·전제 조건

- **보안·컴플라이언스**:
  - 고객 정보, API Key, 내부 비밀번호 등 **민감 정보는 프롬프트·첨부 파일에 넣지 않기**
  - 회사에서 허용한 AI 도구·데이터 반출 정책을 먼저 확인하기

- **사내 정책·도구 제약**:
  - 사내 Git, CI, 코드 저장소 규칙에 맞게 사용하기

- **반드시 사람이 검수할 영역**:
  - **보안·권한·결제·개인정보** 관련 로직
  - AI가 제안한 **테스트 삭제·assertion 약화**
  - **아키텍처·DB 스키마** 등 영향 큰 변경
  - 최종 **코드 리뷰·merge 판단**
